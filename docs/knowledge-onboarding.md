# 真实商家知识库接入与验收

真实资料不能直接整包丢进知识库后就上线。推荐顺序是“盘点—去敏—定稿—导入—检索评测—客服全链路灰度”，这样才知道 AI 为什么答对或答错。

## 1. 向商家收集什么

优先收集已经对外生效、有人负责维护的正式资料：

- 品牌和客服边界：企业简介、服务时间、联系渠道、禁止承诺事项。
- 商品：型号、规格、适用场景、库存和发货限制。
- 交易：下单、支付、发票、优惠、改价规则。
- 物流：发货时效、配送范围、运费、签收异常。
- 售后：退换货、退款时效、保修、质量问题处理。
- 风险：投诉、法律、账户安全和支付争议的人工升级规则。

不要导入客户名单、订单明细、身份证、手机号、支付凭证、后台密码、API Key、内部聊天记录或已经失效的旧制度。

## 2. 导入前整理

每个主题保留一个权威版本，文件名带生效日期，例如 `售后政策-2026-07.md`。冲突内容必须先由商家确认，不能让模型自行选择。扫描 PDF 要检查文字是否可识别；表格要有明确表头；图片中的关键规则应补成文字。

推荐把常见规则整理成 Markdown：

```markdown
# 七天无理由退货

## 适用条件
- 商品签收后 7 天内提出申请。
- 商品、配件和包装保持完整，不影响二次销售。

## 不适用情况
- 定制商品、已拆封且影响卫生安全的商品。

## 客服回答边界
- 不能承诺审核结果；争议订单转人工。
```

## 3. 安全导入

1. 启动 Dify、Chatwoot、API 和 Worker，确认 `/ready` 返回 200。
2. 打开运营看板 `/operations`，输入 `OPERATIONS_API_KEY`。
3. 在“导入企业知识资料”选择文件并点击“开始整理并导入”。
4. 浏览器只把管理密钥放在请求头；服务端先检查大小、扩展名和文件签名，再用 Docling 转为 Markdown，最后由服务端凭证写入当前企业的 Dify 知识库。
5. 支持 PDF、DOC/DOCX、PPT/PPTX、XLS/XLSX、TXT、Markdown、CSV、HTML；单文件上限 20 MB。一次可选多个文件，但会逐个处理，某个失败不会覆盖其他结果。
6. 看板显示“已提交索引”后，到 Dify 确认文档状态完成。不要重复点击同一批资料；需要替换时先在 Dify 停用或删除旧版本。

## 4. 检索评测

为该商家准备 JSONL 评测集，每条至少包含问题和必须检索到的关键词：

```json
{"id":"shipping-001","question":"今天下单什么时候发货？","expected_keywords":["48小时","预售"]}
```

至少覆盖：高频正常问题、同义问法、多轮追问、资料中没有的问题、投诉/支付/账户安全、主动转人工。执行：

```powershell
.\tests\rag-evaluation.ps1 -CasesPath "商家评测集.jsonl"
```

检索通过后，再从真实 Chatwoot 挂件发起同一批问题，验证答案、引用语义、人工接管、人工回复、超时托底和恢复 AI。只有资料内问题稳定回答、资料外问题不编造、高风险问题稳定转人工，才进入灰度。

## 5. 灰度与维护

先让少量真实访客使用 3—7 天，每天查看知识缺口、转人工原因和失败任务。知识修改要保留责任人、生效日期、变更原因和回归问题；补充资料后重新跑相关评测，再标记知识缺口为“已补充”。
